# ForensiVue

A vendor-agnostic DVR/NVR forensic analysis platform: standardized acquisition, parsing, recovery, timeline analysis, custody logging and reporting for surveillance-recorder evidence.

> **IMPORTANT: SYNTHETIC DATA.** All test images are generated by this project and modeled on *assumed* layouts. They are **not** verified vendor formats. Device signatures are placeholders until validated against real disks. Results must not be presented as validated on real Hikvision, Dahua, Uniview or other devices.

## What it does

| Stage | Capability |
|---|---|
| Acquire | Read-only raw (.dd) imaging, single-pass MD5 + SHA-256, re-verification, JSON acquisition record |
| Identify | YAML signature-based vendor identification with ranked confidence and an "unknown" fallback |
| Parse | Plugin parsers (Hikvision-style, Dahua-style, Uniview-style) plus a generic fallback |
| Recover | Index-based recovery of deleted entries and H.264 signature carving, ffprobe-validated |
| Timeline | Timestamp normalization to UTC ISO-8601 (raw value kept), multi-channel timeline, correlation |
| Report | PDF and HTML reports with hashes, findings, custody result, limitations and signature block |
| Custody | Append-only, hash-chained audit log with tamper detection |
| Dashboard | Local web UI (FastAPI + single-page frontend), offline |

## Requirements

- Python 3.11+
- FFmpeg and ffprobe on PATH
- Windows, Linux or macOS

## Setup

```
python -m venv venv
.\venv\Scripts\activate          # Windows
pip install -r requirements.txt
pip install -r requirements_phase3.txt -r requirements_phase4.txt -r requirements_phase9.txt -r requirements_phase10.txt
python -m forensivue.testing.generate_suite   # generates synthetic images in generated/
pytest -v
```

## Usage

```
python -m forensivue.cli acquire --source generated\normal.dd --case CASE-001 --examiner "Your Name"
python -m forensivue.cli timeline --source generated\multi_channel.dd --table
python -m forensivue.cli report --source generated\deleted.dd --case CASE-001 --examiner "Your Name" --out reports\CASE-001
python -m forensivue.cli serve        # dashboard at http://127.0.0.1:8000
```

## Evidence handling principles

- Evidence is opened read-only; source images are never modified.
- Every action is written to a hash-chained audit log (`audit.jsonl`).
- MD5 and SHA-256 are computed for images and every extracted or recovered item.
- Timestamps are stored as UTC with the raw value retained; unparseable times are reported as unknown, never guessed.
- If parsing fails, the tool reports "unrecognized" instead of inventing results.

## Honest limitations

- Synthetic images and assumed layouts only; no real-device validation yet.
- Signatures are placeholders.
- Carving produces some spurious clips and cannot separate interleaved channels.
- AI analytics (motion, object, face detection) are not implemented; planned future work.
- Recovery metrics are measured on 6 synthetic images (see `docs/VALIDATION_REPORT.md`).
